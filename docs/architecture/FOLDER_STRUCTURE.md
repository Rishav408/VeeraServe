## 2. Directory responsibilities

### `docs/`
The documentation suite. Core entry-point documents at the root; topical subfolders for
`architecture/`, `ai/`, and `evaluation/`.

### `frontend/`
React + TypeScript application. `app/` wires providers and routing; `features/` holds feature-scoped
screens/components; `components/ui/` holds shared design-system primitives; `lib/` holds the typed
API client and config.

### `backend/`
FastAPI application. `api/routers` define endpoints; `services` hold business logic and the AI stack
(`agent/`, `rag/`, `tools/`, `stt.py`, `tts.py`); `models`/`schemas` define persistence and
contracts; `db` handles sessions and seeding.

### `data/`
Canonical, version-controlled seed data. `menu.seed.json` is the only menu truth.

### `evaluation/`
The GenAI evaluation harness and its inputs/outputs. Results are generated by code and consumed by
`docs/evaluation/EVALUATION.md` and `docs/ACADEMIC_REPORT.md`.

### `scripts/`
Developer helpers only (seeding, linting, local run). No business logic.

## 3. Dependency direction

```text
frontend  ->  backend API  ->  agent service  ->  tools / RAG / models
                                   ^
                                   |
                         evaluation harness
```

Rules:

- The front end never imports backend code; it talks over HTTP only.
- The agent/tools never import FastAPI or React; they are pure Python services.
- The API depends on services, not the reverse.
- Menu authority lives in one place (the seed + menu service) and is consumed everywhere.

---

## 4. Git hygiene

`.gitignore` must exclude at minimum:

- `node_modules/`, `dist/`, build output, coverage;
- `__pycache__/`, `.venv/`, `.pytest_cache/`, `.ruff_cache/`;
- `.env` and other secret files;
- database files (`*.sqlite`, `*.db`);
- model binaries and large generated artifacts;
- temporary upload/store directories and logs;
- OS/editor cruft (`.DS_Store`, etc.).

Do not commit: caches, datasets, model weights, secrets, or editor/assistant config unless
intentionally shared.

---

## 5. Items not to create prematurely

- Do not add cloud deployment infrastructure before the local prototype works end-to-end.
- Do not add paid AI integrations.
- Do not introduce a second menu source; keep the seed canonical.
- Do not add placeholder analytics that return fabricated values.
- Do not create microservices; a modular monolith is the right size for this project.
